Задание: Qt-приложение для редактирования settings.yaml (sing-box config tool)

Проект: /home/yevstigneyevda/Projects/Python/SingBoxTools/. Там уже есть рабочий бэкенд — sing_box_manager.py (модуль без Qt-зависимостей, содержит всю логику парсинга VLESS-ссылок, валидации settings.yaml, сборки config.json и CLI/TUI). GUI — это НОВЫЙ фронтенд поверх него, а не переписывание логики с нуля. generate_config.py и server_picker.py — тонкие CLI-шимы для обратной совместимости (деплой на сервере, cron), их не трогать.

Технология: PyQt6 (уже в requirements.txt), не PySide — не смешивать.

Публичный API sing_box_manager.py, который GUI должен переиспользовать (НЕ дублировать логику):

load_settings_rt(path) / save_settings_rt(path, data, yaml_rt) — round-trip чтение/запись YAML через ruamel.yaml, сохраняет комментарии. Это основной источник данных для GUI-модели.
load_settings(path) — обычный PyYAML-парсинг (для сборки конфига).
parse_links(path) — список серверов (тегов) из файла ссылок.
validate_proxies(proxies), build_config(settings, outbounds, listen_ip) — валидация/сборка, кидают ConfigError с человекочитаемым текстом.
generate_config_file(settings_path, output=None, links=None, listen_ip=None, exclude_from_auto=None) — генерирует и пишет config.json, возвращает (output_file, stats).
find_stale_refs(rt_settings, all_tags) — список (место, тег) для ссылок на серверы, которых больше нет в текущем файле ссылок (используется в CLI как [!]-маркер, в GUI — как предупреждающая иконка/цвет узла в дереве).
resolve_path(base_dir, path) — относительные пути (links_file, output_file) резолвятся от директории самого settings.yaml.
Структура settings.yaml (актуальный вид, см. файл в репозитории для примера):


listen_ip: <str>
links_file: <path>            # относительный, резолвится от settings.yaml
output_file: <path>
exclude_from_auto: [<str>, ...]
urltest: {url, interval, tolerance}
log: {level, timestamp}
dns: {servers: [...], rules: [], final}
proxies:
  - tag, type (socks|http), port, servers: [<тег сервера>, ...]  # servers может отсутствовать → auto-select
routes:
  <имя>:
    outbound: <тег сервера | pool-<tag> | auto-select | direct>
    domains: [<str>, ...]
Требуемый функционал:

Меню File: Open Project… (открыть settings.yaml через QFileDialog → load_settings_rt), New (создать settings "с нуля" — минимальный валидный скелет: пустые proxies: [], routes: {}, разумные дефолты остального), Save (пишет в текущий открытый путь через save_settings_rt; если файл ещё не имеет пути — вести себя как Save As), Quit. Дополнительно (на усмотрение, но крайне желательно): если есть несохранённые изменения — при New/Open/Quit спрашивать подтверждение (QMessageBox), плюс Save As. Отслеживание "изменено/нет" — через dirty-флаг в модели, взводится любым редактированием.

Левая панель — дерево (QTreeWidget/QTreeView), отражающее структуру settings.yaml одного открытого проекта:

Корень — сам файл проекта (имя/путь).
Узел "Файл ссылок" (links_file) — выбор одного из файлов ссылок в директории проекта (или файловый picker) + предпросмотр количества/списка тегов.
Узел "Output" (output_file) — путь для итогового config.json (file picker).
Узел "DNS" — секция dns.
Узел "Прокси" (proxies) — раскрывается в список прокси по тегам; контекстное меню на узле "Прокси" → добавить новый; контекстное меню на конкретном прокси → удалить/переименовать. Прокси со stale-ссылками (см. find_stale_refs) помечать визуально (иконка/цвет/суффикс, как [!] в CLI).
Узел "Routes" (routes) — аналогично: список маршрутов, добавление/удаление через контекстное меню.
Остальные скалярные поля (listen_ip, urltest, log, exclude_from_auto) — либо отдельными узлами, либо одной формой "Общие настройки" — на усмотрение, лишь бы ничего из текущего settings.yaml не осталось недостижимым из дерева.
Правая панель — QStackedWidget, страница меняется по выбору узла в дереве:

Для "Файл ссылок": file picker (QFileDialog) + список/таблица распарсенных тегов серверов (read-only превью через parse_links).
Для узла конкретного прокси: поля tag/type/port (валидация: уникальность тега/порта, type ∈ {socks, http}, порт 1..65535 — переиспользовать проверки из validate_proxies, не дублировать руками) + список серверов с чекбоксами и текстовым фильтром по подстроке (это прямой аналог filter_and_select/pick_proxy из CLI, только на Qt-виджетах: QLineEdit для фильтра + QListWidget с чекбоксами вместо questionary.checkbox).
Для "DNS": форма под секцию dns (servers/rules/final).
Для узла маршрута: outbound (комбобокс: теги серверов + auto-select/direct/pool-*) + список domains (редактируемый список строк).
Общий пункт меню/тулбар "Сгенерировать config.json" — дергает generate_config_file на текущем сохранённом пути, показывает результат/ошибку (ConfigError) в QMessageBox или статус-баре.
