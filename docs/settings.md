# settings.yaml — справочник по полям

Единственный входной файл инструмента. Читается [`load_settings()`](../sing_box_manager.py:186)
(PyYAML, только чтение), перезаписывается TUI-пикером через
`ruamel.yaml` в round-trip режиме — комментарии и порядок ключей в файле
переживают правку.

Все ошибки формата бросаются как [`ConfigError`](../sing_box_manager.py:73):
сообщение уходит в `stderr`, процесс завершается кодом 1. Неверный ключ в YAML
(None, строка вместо mapping, порт не числом) — это остановка сборки конфига, а
не «молча получилось что-то другое».

Пути `links_file` и `output_file` резолвятся [`resolve_path()`](../sing_box_manager.py:441)
**относительно каталога самого YAML-файла**, а не текущего каталога процесса.
Это позволяет запускать инструмент из любого места (cron, TUI, тесты) и получать
`config.json` рядом с настройками.

## Верхний уровень

### `listen_ip`

* тип: строка, обязательна непустая; дефолт — `127.0.0.1`;
* переопределяется флагом `--listen-ip`;
* адрес, который попадает в `inbounds[].listen`: на нём приложения видят
  прокси-инбаунды (SOCKS, HTTP и mixed). `127.0.0.1` — только своя машина,
  `10.95.2.1`/`0.0.0.0` —
  раздача прокси в локальную сеть (и, соответственно, вопрос firewall).

### `links_file`

* тип: строка-путь; дефолт — `links.txt`; переопределяется флагом `--links`;
* файл подписки: по одной `vless://` ссылке на строку. Пустые строки и мусор
  игнорируются, но если **ни одной** валидной ссылки нет — `ConfigError`
  («валидных VLESS-ссылок не обнаружено», [`parse_links()`](../sing_box_manager.py:157)).

Из ссылок извлекаются `uuid`, сервер, порт (по умолчанию 443) и тег из fragment
(`#🇫🇮 Finland - Helsinki 1`); без fragment тег будет `vpnd-<host>`
([`parse_vless()`](../sing_box_manager.py:90)). Параметры `security=reality`
(`pbk`, `sid`, `sni`, `flow`, `fp`) и `security=tls` (`sni`, `fp`) превращаются в
`tls`-блок outbound; при отсутствии `security` — чистый TCP без `tls` и `flow`.
Reality-ссылка без `pbk` отбрасывается, как и ссылка без uuid/сервера.

### `output_file`

* тип: строка-путь; дефолт — `config.json`; переопределяется флагом `--output`
  (есть алиас `--config`);
* куда писать итоговый конфиг sing-box. Отсутствующие каталоги создаются
  ([`write_json()`](../sing_box_manager.py:446)), так что `output_file: /etc/sing-box/config.json`
  сработает, если хватает прав.

### `exclude_from_auto`

* тип: список непустых строк (префиксы тегов); дефолт — `["🇷🇺"]`
  ([`DEFAULT_EXCLUDE`](../sing_box_manager.py:65)); переопределяется флагом
  `--exclude-from-auto`;
* серверы, чьи теги начинаются с одного из префиксов, не попадают в общий
  пул `auto-select`, но остаются отдельными outbounds и могут быть выбраны
  явно в `servers` или в доменном правиле. Замысел — РКН-ноды: у них минимальный
  RTT, `urltest` выбрал бы их первыми, а трафик при этом не покидает РФ.
  Проверка на непустые строки — [`validate_exclude()`](../sing_box_manager.py:292).

## `urltest`

Параметры всех urltest-пулов (и `auto-select`, и `pool-<tag>`) — один блок на
все пулы, [`urltest_block()`](../sing_box_manager.py:273).

| Ключ | Тип | Дефолт | Смысл |
| --- | --- | --- | --- |
| `url` | непустая строка | `https://gstatic.com` | что пул дёргает для замера |
| `interval` | непустая строка | `3m` | период перепроверки |
| `tolerance` | целое число | `50` | разброс задержек, при котором нода ещё считается равной лучшей |

Секция необязательна: без неё берутся дефолты. Неверный тип любого поля —
`ConfigError` с именем поля.

## `log`

* тип: mapping; дефолт `{}`;
* отдаётся в config.json как есть (`log.level`, `log.timestamp`, ...).

## `dns`

* тип: mapping; дефолт `{}`;
* отдаётся в config.json как есть (`servers`, `rules`, `final`). Если секции нет
  или она пуста — генерация продолжается с предупреждением в `stderr`, а
  `route.default_domain_resolver` всё равно указывает на `dns-local`.
* В sing-box 1.14 у `dns.rules` нет элемента `outbound`, поэтому политика
  «резолвить через туннель» задаётся не правилом, а `final` (например,
  `dns-remote`). Комментарий об этом живёт прямо в [`python/settings.yaml`](../../settings.yaml:33).

## `proxies`

Главная секция: **каждый элемент = отдельный inbound** (SOCKS, HTTP или mixed),
который указывают приложения. Валидация и нормализация —
[`validate_proxies()`](../sing_box_manager.py:225), сборка inbounds —
[`build_inbounds()`](../sing_box_manager.py:302).

| Ключ | Тип | Обязателен | Смысл |
| --- | --- | --- | --- |
| `tag` | непустая строка | да | тег inbound и основа имени пула `pool-<tag>` |
| `type` | `socks`, `http` или `mixed` | да | протокол inbound: `mixed` — один порт и для SOCKS4/4a/5, и для HTTP CONNECT (протокол различается по первым байтам соединения) |
| `port` | целое 1..65535 | да | порт для приложений |
| `servers` | список непустых строк или одна строка | нет | теги серверов из `links_file`; строка нормализуется в список; пусто/опущено — пула нет, работает `auto-select` |

Что проверяется жёстко:

* отсутствие самой секции или пустой список → «в настройках отсутствует секция
  proxies (нужен хотя бы один прокси)»;
* дубликаты `tag` и `port` → отдельные ошибки «дубль тега инбаунда» /
  «дубль порта инбаунда» (порт занят — приложения не смогут отличить прокси);
* `port` не числом (`"54321"`, `True`, `54321.5`) или вне диапазона → ошибка;
* `type` не из `("socks", "http", "mixed")` → ошибка со списком допустимых типов;
* `servers` не список строк (например, число или mapping внутри списка) → ошибка;
* тег сервера из `servers`, которого нет в текущей подписке → ошибка
  [`build_pools()`](../sing_box_manager.py:322) с перечислением доступных тегов.
  Это не «предупреждение и пустой пул», а остановка: иначе `urltest` с одним
  битым именем тихо превратился бы в неработающий прокси.

Пример: `main-socks` без `servers` живёт на `auto-select`, а `apps-http` со
списком из двух финско-нидерландских нод получает свой `pool-apps-http` — чтобы
трафик приложения шёл строго через одну из них, а не через любую случайную ноду
подписки.

## `routes`

Доменные правила поверх прокси. Топ-уровень — mapping «имя правила → правило»:
имя используется только в сообщениях (в том числе в предупреждениях
`find_stale_refs`), в config.json попадают `domain_suffix` и `outbound`.

| Ключ | Тип | Дефолт | Смысл |
| --- | --- | --- | --- |
| `outbound` | строка | `auto-select` | куда отправлять домены: тег сервера, `pool-<tag>`, `auto-select` или `direct` |
| `domains` | список строк или одна строка | `[]` | доменные суффиксы (`telegram.org`, `googlevideo.com`) |

Если `outbound` не совпадает ни с одним известным outbound, генерация продолжается,
но в `stderr` печатается предупреждение «маршрут '<имя>' ссылается на неизвестный
outbound» — правило с несуществующим outbound в sing-box всё равно не сработает,
а заметить опечатку в конфиге иначе почти невозможно. Правила добавляются
после системных (см. ниже), поэтому доменное правило сильнее закрепления
инбаунда за пулом.

## Как это превращается в config.json

Порядок сборки — [`build_config()`](../sing_box_manager.py:376):

```
outbounds = [auto-select (urltest)] + [direct] + [pool-<tag>...] + [все VLESS-серверы]
inbounds  = по одному на каждый proxies[]
route.rules = [hijack-dns] [sniff] [закрепления inbound→pool-<tag>] [доменные правила]
route.final = auto-select
route.default_domain_resolver = dns-local
```

Порядок и состав правил задаёт [`build_rules()`](../sing_box_manager.py:344):

1. `{"protocol": "dns", "action": "hijack-dns"}` — DNS перехватывается, иначе
   запросы утекут мимо прокси;
2. `{"inbound": [...все...], "action": "sniff"}` — определение протокола по
   содержимому; действие не финальное, поэтому перебор outbound продолжается;
3. по правилу `{"inbound": ["<tag>"], "outbound": "pool-<tag>"}` на каждый
   прокси с непустым `servers` — так инбаунд привязывается к своим нодам
   (в sing-box 1.14 `inbound.detour` — это чейнинг инбаундов, а не выбор
   аутбаунда, поэтому нужен именно route-rule);
4. доменные правила из `routes` — накладываются поверх.

`stats`, который возвращает [`generate_config_file()`](../sing_box_manager.py:459)
и печатает [`generate_and_report()`](../sing_box_manager.py:508), считает
`servers`, `inbounds`, `pools`, `auto_count` и список `excluded` — именно по ним
видно, что `exclude_from_auto` не съел вообще все серверы.

## Частые ошибки

* `links_file` указан относительно, а запуск идёт из другого каталога — не
  проблема: пути идут от каталога YAML. Проблема — указать файл, которого рядом
  нет: «файл ссылок ... не найден».
* Два прокси с одинаковым `port` — приложения будут ходить «не туда». Ошибка
  ловится на старте, а не в рантайме.
* Тег с `#2` (автосуффикс из [`dedup_tags()`](../sing_box_manager.py:146)) в
  `servers` — нормальный тег, если в подписке действительно две ноды с одинаковым
  названием. Но при обновлении подписки порядок может измениться, и `find_stale_refs`
  это покажет.
* `exclude_from_auto: []` — не «выключить исключения», а «ничего не исключать»:
  так российские ноды возвращаются в `auto-select`. Чтобы отключить фильтр,
  так и пишется — пустым списком.
* Пустой `auto-select` (все теги исключены) не роняет генерацию: в `stderr`
  попадёт предупреждение, а `route.final: auto-select` останется без кандидатов —
  проверяйте `stats.auto_count`.
