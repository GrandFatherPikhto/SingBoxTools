# Qt6-GUI — редактор settings.yaml

Новый фронтенд поверх того же бэкенда [`sing_box_manager.py`](../sing_box_manager.py:1):
бэкенд не знает про Qt, GUI не дублирует его логику. Парсинг VLESS, валидация
`proxies`/`urltest`, сборка `config.json`, поиск протухших ссылок — всё берётся
из бэкенда; GUI добавляет окно, дерево проекта и формы.

## Запуск

```bash
./gui.py                          # новый проект (минимальный валидный скелет)
./gui.py path/to/settings.yaml    # открыть существующий проект
```

`gui.py` — единственная точка входа: он лишь создаёт `QApplication` и показывает
главное окно. Вся библиотечная часть лежит в пакете [`generator/`](../generator/__init__.py:1).

Зависимости: `PyQt6` (GUI), `ruamel.yaml` (round-trip запись с сохранением
комментариев), `pyyaml`. Тесты дополнительно требуют `pytest-qt` — см.
[`requirements.txt`](../requirements.txt:1).

## Как устроено

| Модуль | Роль |
| --- | --- |
| [`gui.py`](../gui.py:1) | точка входа: `QApplication` + `MainWindow` |
| [`generator/_backend.py`](../generator/_backend.py:1) | единственное место, где пакет импортирует `sing_box_manager` |
| [`generator/model.py`](../generator/model.py:1) | `ProjectModel` — загрузка/сохранение, dirty-флаг, правки, дерево. **Без Qt** |
| [`generator/validation.py`](../generator/validation.py:1) | проверка формы прокси через `validate_proxies` бэкенда |
| [`generator/widgets.py`](../generator/widgets.py:1) | страницы QStackedWidget: прокси, маршрут, DNS, общие, ссылки, output |
| [`generator/main_window.py`](../generator/main_window.py:1) | `MainWindow`: меню, дерево, контекстные меню, генерация |

Разделение сделано намеренно: логика правок (построение узлов дерева,
dirty-tracking, валидация) живёт в Qt-независимом `ProjectModel`, поэтому её
можно тестировать без `qtbot`, а Qt-слоты окна — тонкая обвязка над моделью.

## Меню «Файл»

| Пункт | Горячая клавиша | Что делает |
| --- | --- | --- |
| Создать | `Ctrl+N` | минимальный валидный скелет: пустые `proxies`/`routes`, разумные дефолты остального |
| Открыть проект… | `Ctrl+O` | `QFileDialog` → [`load_settings_rt()`](../sing_box_manager.py:197) (комментарии сохраняются) |
| Сохранить | `Ctrl+S` | [`save_settings_rt()`](../sing_box_manager.py:207); если пути ещё нет — ведёт себя как «Сохранить как…» |
| Сохранить как… | `Ctrl+Shift+S` | запись в новый файл |
| **Сгенерировать конфигурацию** | `Ctrl+G` | [`generate_config_file()`](../sing_box_manager.py:459) на текущем пути; результат и ошибки — в QMessageBox и статус-баре |
| Выход | `Ctrl+Q` | с подтверждением, если есть несохранённые изменения |

«Сгенерировать конфигурацию» продублирован в меню **Tools** и на тулбаре.
Перед генерацией, если в проекте есть несохранённые изменения, окно предлагает
сохранить (Save/Discard/Cancel) — из неактуального YAML на диске генерация молча
не запускается. Ошибка [`ConfigError`](../sing_box_manager.py:73) (например,
`прокси 'x' ссылается на несуществующие серверы: …`) показывается текстом как есть.

Dirty-флаг взводится любым редактированием; в заголовке окна появляется `*`.
При `Создать`/`Открыть`/`Выход` с несохранёнными изменениями окно спрашивает
подтверждение.

## Дерево проекта (левая панель)

```
settings.yaml
├── Файл ссылок: links.txt        — выбор файла + предпросмотр тегов (parse_links)
├── Output: config.json           — путь для итогового config.json
├── Общие настройки               — listen_ip, urltest, log, exclude_from_auto
├── DNS                           — servers / rules / final
├── Прокси                        — по узлу на каждый прокси (контекстное меню)
└── Routes                        — по узлу на каждый маршрут (контекстное меню)
```

* Контекстное меню на узле **Прокси** → добавить новый; на конкретном прокси →
  переименовать/удалить. Аналогично для **Routes**.
* Прокси и маршруты со ссылками на исчезнувшие серверы (см.
  [`find_stale_refs()`](../sing_box_manager.py:544)) помечаются красным и
  суффиксом `[!] нет в списке серверов: …` / `[!] неизвестный outbound: …` —
  как `[!]` в CLI-TUI.

## Правая панель (QStackedWidget)

* **Файл ссылок** — picker + read-only список распарсенных тегов.
* **Прокси** — `tag`/`type`/`port` + список серверов с чекбоксами и фильтром по
  подстроке (прямой аналог `filter_and_select` из CLI, но на Qt-виджетах).
  Валидация (уникальность тега/порта, `type ∈ {socks, http}`, порт 1..65535)
  идёт через `validate_proxies` бэкенда и **блокирует** применение, а не тихо
  портит YAML.
* **DNS** — `final` + `servers`/`rules` YAML-списками.
* **Маршрут** — `outbound` (комбобокс: теги серверов, `auto-select`, `direct`,
  `pool-*`) + редактируемый список `domains`.

## Тесты

GUI-тесты живут в [`tests/`](../tests/test_gui_window.py:1) и работают через
`qtbot` на offscreen-платформе (`QT_QPA_PLATFORM=offscreen` выставляется в
[`tests/conftest.py`](../tests/conftest.py:1)), без реального дисплея:

```bash
.venv/bin/python -m pytest tests -q
```

* [`tests/test_gui_model.py`](../tests/test_gui_model.py:1) — модель без Qt:
  New/Open, дерево, stale-ссылки, CRUD прокси/маршрутов, валидация, round-trip
  save (комментарии и остальной YAML не ломаются);
* [`tests/test_gui_window.py`](../tests/test_gui_window.py:1) — окно через qtbot:
  построение дерева, добавление/удаление через обработчики контекстного меню,
  блокировка невалидной формы, подсветка stale, Save в `tmp_path` и оба сценария
  «Сгенерировать конфигурацию» (валидный проект → config.json; битая ссылка →
  ошибка через сигнал, без падения).

Модальные диалоги в тестах заглушаются, а результаты/ошибки генерации
дополнительно перехватываются сигналами окна (`generation_done`, `config_error`,
`config_generated`), поэтому проверки не зависят от текста QMessageBox.
